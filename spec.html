1. Goals & non-goals

Goals

  • Minimum taps. After players exist: open page → tap New game → only number taps until the session is over. For 2 players that is 1 + 18 + 16 + 18 = 53 taps; in general 1 + N × 26.
  • Always obvious: whose score is being entered, which course and hole, that player's running total, and their score on the prior hole.
  • Single HTML file, no dependencies, no build step, no network calls. All state in localStorage.
  • Designed for a portrait phone held in one hand.
  • Fun payoff at the end: stats, personal records, percentiles.

Non-goals (v1) Added

  • Accounts, sync, or a backend. Moving data between devices is done by export/import.
  • Multiple simultaneous scorekeepers / devices.
  • Adding or removing a player mid-game (use Skip for someone who drops out).
  • A course editor UI. Courses are a config object in the source; adding a venue means editing the file.

2. Venue & course config

One venue, three courses played back to back in this fixed order.

#CourseHolesParScoring
1Mini Golf93 each (27)Strokes, 1–8, 8-stroke cap. Lower is better.
2Aces8noneOne shot sets the score, 1–8. Lower is better.
3Duffleboard9noneOne shot sets the score, 1–8. Lower is better.

Decided All three courses score 1–8, lower is better. On Mini Golf, 8 is the stroke cap: if you haven't holed out by stroke 8, you record an 8.

Config lives in a single constant so another venue can be added later without touching logic: Added

const VENUES = [{
  id: "redmond", name: "Redmond",
  courses: [
    { id: "redmond-mini",  name: "Mini Golf",   holes: 9, par: [3,3,3,3,3,3,3,3,3],
      lowerIsBetter: true, keys: [1,2,3,4,5,6,7,8] },
    { id: "redmond-aces",  name: "Aces",        holes: 8, par: null,
      lowerIsBetter: true, keys: [1,2,3,4,5,6,7,8] },
    { id: "redmond-duff",  name: "Duffleboard", holes: 9, par: null,
      lowerIsBetter: true, keys: [1,2,3,4,5,6,7,8] }
  ]
}];
  • ids are permanent: records and percentiles are keyed by course id, so renaming a course keeps its history. If a course's layout really changes, give it a new id.
  • lowerIsBetter controls winner, turn order, records and percentiles for that course.
  • keys are the 8 values on the numpad (the 9th key is always S). All Redmond courses use 1–8. The setting exists so a future venue can use different values.
  • With only one venue, there is no venue picker. A picker appears only when VENUES.length > 1.

3.1 Player setup (first run, or "Players" from Home)

  • Shown automatically when no players are stored.
  • A text field plus Add; Enter also adds. Names are trimmed, must be non-empty and unique (case-insensitive).
  • Saved players appear as a list with a checkbox for "playing today", plus rename and delete. Added Deleting a player who has history only hides them (history and stats are kept).
  • 1–6 players per game. Added Six columns is about the most that fits a 360 px wide screen at a readable size.
  • Who's playing today is remembered. The next New game reuses it with no extra screen.

3.2 Home

  • Resume game: the big primary button, shown only if a game is in progress, with a summary like "Aces, hole 3 · started 2:14 pm".
  • New game: the primary button when nothing is in progress, secondary otherwise. If a game is in progress, show a confirm ("Abandon current game?"). That extra tap only happens in this case. Added An abandoned game is kept in history as abandoned and left out of stats.
  • Small links: Players, History, Export all data, Import data.
  • Line showing today's players: "Playing: Adam, Sam, Jo". Tapping it opens Player setup.

3.3 New game

  • One tap creates the game: all 3 scorecards, empty, with the remembered players.
  • Random first order: the hole-1 order is a random shuffle of the players (Fisher–Yates over crypto.getRandomValues). A banner shows "🎲 Sam goes first, then Adam, Jo" and fades after the first score. No confirm tap.
  • Re-roll link on the banner, usable until the first score is entered. Added

Layout, top to bottom

  1. Sticky "now up" bar: course · hole X / H · par; big player name; that player's course total (with ± par where par exists) and their score on the prior hole.
  2. Three scorecards stacked vertically: N player columns × H hole rows plus a total row. Columns stay in a fixed order (the order from setup) so they don't jump around. The current hole row is shaded and the cell being entered is outlined.
  3. Numpad fixed to the bottom (thumb zone): a 3×3 grid of 1–8 and S, with keys at least 64 px tall.
  4. Small row below the pad: Undo, Redo, and a menu (⋯) for Home, copy scores, and end game early.

Making "whose turn" unmistakable Added

  • Each player gets a stable color. The now-up bar and the numpad take the active player's color, so the color changes on every hand-off.
  • Small order badges (1, 2, 3) in the column headers show this hole's playing order. The next player is shown in the bar as "next: Jo".
  • After each tap a quick toast confirms it, e.g. "Adam · 2 ✓", and the cell flashes.
  • The page auto-scrolls so the current row is visible above the pad. Finished cards collapse to their total row, and tapping a card expands it again.

Prior hole score: the current player's score on the previous hole of this course. On hole 1 of Aces or Duffleboard, show the previous course's total instead (e.g. "Mini Golf: 26"). Added

5. Turn order rules

  • Within a hole, each player finishes before the next starts. The app enters scores in this hole's order, one player at a time.
  • The next hole's order sorts players by this hole's score, best first (using the course's lowerIsBetter).
  • Ties keep their order from the current hole (stable sort). Added This matches the usual "honors stay" convention.
  • Skip ranks as worst on that hole. Several skips keep their current relative order. Added
  • Across courses Decided: hole 1 of the next course follows the previous course's final standings, not its last hole. Best total goes first. If the lead was tied, the playoff winner (§7.1) goes first. Any other ties keep their order from the previous course's last hole. Players with an unresolved skip on the previous course rank after everyone with a complete card.
  • Playoff holes follow the same per-hole rule, applied only to the players in the playoff (§7.1).
  • Order is derived, never stored: it is recomputed from the scores (plus the stored hole-1 shuffle). That keeps undo and edits consistent with no extra bookkeeping.

6. Numpad, skip, undo/redo, edits

6.1 Numpad

  • One tap records the score for the highlighted player/hole and moves on. There is no "enter" key.
  • Keys come from the course's keys (default 1–8). The 9th key is always S.
  • Fat-finger guard Added: ignore taps for about 250 ms after a score is recorded, so a double tap doesn't score the next player. Use pointerdown for instant response and touch-action: manipulation to block double-tap zoom.
  • Short vibration on tap where supported (navigator.vibrate(10); Android only, so skipped on iOS).

6.2 Skip (S)

S means the player didn't play that hole (bathroom break, hole closed, a kid wandered off). It is shown as S in the cell.

Decided: a skip records no data. It adds nothing to the total, and the total shows a marker (e.g. "24*"). Skipped holes can be replayed at the end of the game (§7.2). A course that still has a skip is incomplete for that player: it stays in history, but it can't win the course, set a record, or count toward percentiles.

6.3 Undo / Redo

  • The stack holds actions: {type:"set", course, hole, player, prev, next}. Undo restores prev and moves the cursor back to that cell. Redo re-applies.
  • Any new action after an undo clears the redo stack (standard behavior).
  • The stack is persisted with the game, so undo still works after a reload or Resume. Added
  • Undo can cross course boundaries (undoing the first Aces score goes back into Mini Golf). It cannot undo across "game finished": once the stats screen appears, use Reopen game instead. Added
  • Undo/Redo are disabled (greyed out) when their stack is empty.

6.4 Editing an earlier cell Added

Undo is the wrong tool for fixing a mistake from five holes ago. So:

  • Tapping any filled cell selects it. The bar turns amber and reads "Editing Jo · Hole 2". The next numpad tap overwrites that cell (an undoable set action), and the cursor returns to the live position.
  • Tapping the same cell again, or the bar, cancels the edit.
  • Turn order for holes not yet played is recomputed. Holes already entered are left alone.

7. Course transitions & game end

  • After the last regulation score of a course, the app checks for a tie for first:
    • No tie: the app moves straight to the next course with no tap. A toast shows the result, e.g. "Mini Golf: Sam wins, 24 – 27. Aces next". The finished card collapses and the next card scrolls into view.
    • Tie for first: the app goes straight into a playoff (§7.1), also with no tap.
  • When Duffleboard is resolved (including any playoff), the game moves to the end-of-game check (§7.2), then the Stats screen.
  • End early (⋯ menu, with confirm): marks unentered cells as not played and finishes the game. Only fully played courses count toward wins, records and percentiles. Added
  • Reopen game (Stats screen): returns to scoring to fix a mistake. Wins, playoffs and stats are recomputed when it finishes again. Added

7.1 Playoff holes (course tie-break) Decided

If two or more players tie for the lowest course total, they play sudden-death playoff holes to decide the course win.

  • Who plays: only the players tied for first. Players tied for 2nd or lower don't have a playoff, because only the win counts.
  • Which holes: replay from hole 1 (P1 = hole 1, P2 = hole 2, …). If the playoff runs past the course's last hole, wrap back to hole 1.
  • Win condition: after each playoff hole, the player with a lower score than every other player in the playoff wins. If two or more tie for the lowest score on that hole, those players continue to the next playoff hole and anyone who scored higher is out. With two players, that simply means the first to beat the other wins. With three or more, the field narrows each hole.
  • Order: P1 uses the order of the course's last regulation hole, filtered to the tied players. After that, the normal per-hole rule applies.
  • Display: playoff rows appear on that course's card below the total row, labeled P1 · h1, P2 · h2, …, with non-participants' cells greyed out. The now-up bar reads "Playoff · Mini Golf hole 1" in a distinct accent color. When it's decided, the toast reads "Sam wins the Mini Golf playoff on P2".
  • Scoring effect: playoff strokes do not change course totals, records, percentiles or per-hole stats. They only decide the course win and the next course's order. The numpad, Undo/Redo and cell edits work in playoffs exactly as in regulation. Undoing the deciding playoff score reopens the playoff.
  • Skip in a playoff: S means the player is out of the playoff (forfeit). If only one player is left, they win.
  • Ties involving incomplete cards: a player with a skip on that course can't win it, so they're never in its playoff. If skips are replayed later (§7.2) and that creates a tie for first, the playoff happens then.

7.2 End of game: replay skipped holes Decided

  • If no skips remain, the game finishes immediately: status becomes finished, finishedAt is set, and the Stats screen opens. The tap count is unchanged.
  • If skips remain, a sheet lists them ("Adam: Mini Golf 4, Aces 2") with two buttons: Replay skipped holes and Finish anyway.
    • Replay walks the cursor through each skipped cell, in course and hole order, then in column order. The now-up bar reads "Replay · Adam · Mini Golf hole 4". Entering a number replaces the S. Tapping S again leaves the hole skipped. When the last one is done, course winners are recomputed, and any new tie for first triggers a playoff (§7.1) before the Stats screen.
    • Finish anyway: remaining skips stay. Those players' courses are incomplete (no win, no record, no percentile).
  • The course winner shown during play (toasts, next-course order) is provisional if a player with a skip could still change it by replaying. The toast says so: "Mini Golf: Sam leads (Adam has 1 skip)".

8. Post-game stats

One scrollable screen, one section per course plus a session summary.

8.1 Per course

  • Final standings with totals (and ± par for Mini Golf). The winner gets a 👑. If a playoff decided it, a note says "won in a playoff on P2".
  • Personal course record 🎉: if a player's total beats their best complete prior total on that course id, show a celebration card and a CSS confetti burst. A first-ever round counts as a record only quietly ("First round, record set"), not with confetti. Matching a record shows "Tied your best".
  • Percentile: "Better than 82% of all Mini Golf rounds".
    • Definition: (rounds beaten + 0.5 × rounds tied) / prior rounds × 100, rounded.
    • Decided Show both:
      • All players: compared with every complete round on that course by anyone before this game. "Better than 82% of all Mini Golf rounds"
      • Personal: compared with the player's own earlier complete rounds. "Better than 70% of your rounds · your 3rd best of 11"
    • Each percentile has its own threshold: it appears only with at least 5 prior rounds in its pool.
    • Shown only when there are at least 5 prior rounds. Otherwise show "Round 3 on record, percentiles start at 5". Added
  • Highlights Added: holes-in-one (Mini Golf score of 1), best hole relative to the group, and hardest hole today (highest average).

8.2 Session summary Added

  • Decided The session winner is whoever wins the most courses. Thanks to playoffs, every complete course has exactly one winner. Totals from different courses aren't added together.
  • A tie in course wins is possible with 3 or more players (1–1–1). In that case they're co-champions; no extra tie-break.
  • Lifetime head-to-head among today's players: "Adam vs Sam: 7–4 in course wins".
  • Buttons: Copy scores, Reopen game, Home.

8.3 History screen Added

A list of past games (date, players, course winners). Tapping one shows its read-only scorecards and stats. Per-player view: rounds played per course, best, average, and a simple trend.

9.2 Export all data

  • Copies the full storage object as pretty-printed JSON, wrapped in a small envelope: { app: "golf-scorecard", schemaVersion, exportedAt, data }.
  • Also offers Email it (mailto: with the JSON in the body) and Download .json. Long mailto: bodies get truncated on some clients, so copy-to-clipboard stays the main path. Added
  • The Home screen shows "Last export: 23 days ago" as a gentle backup reminder. Added

9.3 Import Added

Export with no import is only half a backup. Import exists because localStorage is tied to a browser and URL (see §11). Without it, data can't move to a new phone, survive a hosting move, or be recovered after Safari clears storage.

  • Paste JSON into a textarea (or pick a file) → validate → show a preview ("4 players, 17 games") → choose Merge (default; dedupes by id) or Replace (asks to confirm and exports the current data first automatically).
  • Older schemaVersions are migrated. Newer ones are rejected with a clear message.

9.4 Clipboard mechanics

Use navigator.clipboard.writeText. It only works in a secure context (https or localhost), so when it isn't available or fails, fall back to a hidden textarea with select() + document.execCommand("copy"). If that also fails, show the text in a selectable modal. Always confirm with a toast: "Copied ✓".

10. Persistence & data model

One localStorage key, golfScorecard.v1, holding a single JSON object. It is written after every action (it's small, and synchronous writes are fine).

{
  schemaVersion: 1,
  players: [ { id, name, color, hidden: false, createdAt } ],
  lastRoster: [playerId, ...],          // "playing today"
  currentGameId: "g_..." | null,
  lastExportAt: ISO | null,
  games: [{
    id, venueId: "redmond",
    status: "active" | "finished" | "abandoned",
    startedAt, finishedAt,
    playerIds: [...],                   // column order
    firstOrder: [...],                  // random hole-1 order
    courses: [{
      courseId: "redmond-mini",
      scores: { [playerId]: [3, 2, "S", null, ...] },  // null = not entered
      playoff: null | {                                 // only if tied for first
        playerIds: [...],                               // who's in it
        scores: { [playerId]: [2, 3, ...] }             // index 0 = P1 (hole 1)
      }
    }, ...],
    replayQueue: null | [{ course, hole, playerId }],   // set when "Replay skipped holes" is chosen
    undo: [action, ...], redo: [action, ...]
  }]
}
  • The cursor (current course/hole/player) is derived, never stored, so it can't drift out of sync. It is the first empty cell in turn order. A course with an unfinished playoff takes priority over the next course's hole 1. During replay it is the head of replayQueue.
  • Course winners, playoff eliminations, and the playoff winner are all derived from the scores too. Undo actions also cover playoff cells and replay steps ({type:"set", course, hole, player, playoff: true, ...}).
  • Records, percentiles, and history stats are computed from games when needed. A few hundred games is trivial to scan.
  • Ids: crypto.randomUUID(), with a fallback for older browsers.
  • If a write fails (quota or private mode), show a red banner saying scores are not being saved, with an Export button.
  • Changing the storage shape means bumping schemaVersion and adding a migration function. Never break old data.

11. Phone & browser concerns Added

  • Hosting decides where the data lives. localStorage belongs to the origin (scheme + host). Opening file:// on a phone is awkward and breaks the clipboard API. Decided It will be hosted on GitHub Pages once the repo has a remote (not yet). Until then, test on a desktop browser, or serve it on the LAN (e.g. python -m http.server) for a phone. LAN http isn't a secure context, so the clipboard fallback (§9.4) gets exercised. Treat data from before Pages as test data, or move it with export → import.
  • iOS Safari storage eviction. Safari can delete localStorage for sites that haven't been visited in 7 days, unless the site was added to the Home Screen. The app should (a) suggest Add to Home Screen on first run on iOS, (b) call navigator.storage.persist() where available, and (c) show the "last export" reminder.
  • Screen sleep. Request a Screen Wake Lock (navigator.wakeLock.request("screen")) while the scoring screen is open, and re-request it on visibilitychange. This saves unlocking the phone every hole.
  • Offline. A single file with no service worker still needs the network to load, but works offline once open, and Resume survives a reload once you have signal again. A service worker would need a second file, so it's out of scope for v1.
  • Viewport: width=device-width, initial-scale=1, viewport-fit=cover; respect env(safe-area-inset-bottom) under the numpad; overscroll-behavior: none to stop accidental pull-to-refresh.
  • Theme: follow the system light/dark setting. High contrast for bright sunlight. System font, large type (the player name at about 28 px or more).
  • Accessibility: numpad keys are real <button>s; the now-up bar is an aria-live="polite" region; colors are never the only cue (the name text is always shown).

12. Edge cases Added

CaseBehavior
Single playerWorks. No order logic and no playoffs; the player wins every complete course. Percentiles still compare against all players' rounds.
Everyone ties a holeOrder is unchanged.
Tab reloaded / phone restarts mid-gameHome shows Resume, which lands on the exact cell.
Two tabs openListen to the storage event and reload state, so the last writer doesn't silently win.
Player renamedHistory follows the id, so old games show the new name.
Player plays every hole but S on oneTotal shows *. Offered for replay at game end. If still skipped, that course is incomplete: no win, record, or percentile.
Score above 8 on Mini Golf8 is the stroke cap, so record 8.
Everyone tied for first on a courseEveryone goes into the playoff.
Playoff passes the last holeWraps back to hole 1 (P10 on Mini Golf = hole 1).
Three-way tie, one player beaten on P1That player is out. The other two continue to P2.

13. Acceptance criteria

  1. With no stored data, the page opens to Player setup. After adding 2 players and tapping Start, scoring begins.
  2. With players stored and no ties or skips, a full 2-player session takes exactly 53 taps: New game plus 52 numpad taps, ending on the Stats screen. With 3 players it takes 79. Each playoff hole adds one tap per remaining player. Skips add one tap at game end plus one per replayed hole.
  3. A tie for first on a course starts playoff holes from hole 1 with no extra tap. The first player to score strictly lower than all remaining players wins the course. Playoff strokes don't change course totals.
  4. Course 2 and 3 hole-1 order follows the previous course's standings, with the playoff winner first.
  5. At every point before game end, the screen shows course, hole, active player name, that player's course total, and their prior-hole score, with no scrolling.
  6. Hole N+1 order equals hole N scores sorted best first, with stable ties and skips last.
  7. Undo × k followed by Redo × k returns to an identical state, including after a page reload in between.
  8. Killing the browser mid-hole and reopening, then tapping Resume, lands on the same cell with the same undo stack.
  9. Copy scores produces the plain-text format in §9.1. Export all → Import (Replace) on a clean browser gives identical history and stats.
  10. A new best complete round triggers the record celebration. Percentiles appear only after 5 or more prior rounds on that course.
  11. Works in current iOS Safari and Android Chrome at 360–430 px width with no horizontal scroll.
  12. index.html loads nothing external: no CDN, fonts, or images other than inline/emoji.
